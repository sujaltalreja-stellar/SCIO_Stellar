# SEO and code-cleanup audit: Stellar SCIO

**Date:** 2026-11-26 · **Live site:** https://www.stellarscio.app · **Repo / branch:** 12_SCIO @ feature-seo-geo
**Front-ends:**
- Marketing site (`/`, `/platform`, `/platform/integrations`, `/use-cases`, `/why-scio`, `/erp-experts`, `/faq`, `/contact`): Vite 8 + React 19 SPA, prerendered per route by `scripts/prerender-seo.mjs`, hosted on Vercel. **Public**, full audit.
- SCIO app (`/app/*`, legacy `/demo/*`, `/?launch=1`, `/?industry=`): same bundle, lazy-loaded. **Private**, noindex and cleanup checks only.
- `api/index.js` (Vercel function) + `convex/`: **backend**, cleanup only.
- `Renewable Energy/`: separate older Vite project, excluded from deploys by `.vercelignore`. Repo cleanup only.

## Summary
The site already has strong SEO foundations. Each public route gets its own prerendered HTML with a unique title, description, canonical, Open Graph tags, JSON-LD and a plain-text copy of its content. There are also `llms.txt` files for AI answer engines, a clean sitemap, a sensible robots.txt, HTTPS with HSTS, one canonical host (apex and http both 308 to `https://www`), and long-lived caching on hashed assets.

The biggest problem is that **every unknown URL returns 200 with the homepage** (a "soft 404"). Old retired URLs also only redirect in JavaScript, which crawlers often don't run. The private `/app` pages tell Google "index, follow". Most meta descriptions are too long, so Google will cut them off, and five pages give non-JS crawlers fewer than 60 words. On performance, the homepage hero loads five full-size photos on every device, one of them 368 KB, and the repo carries unused images and files.

The batches below fix these without changing how the site looks.

### Batch 1: Crawling, indexing and redirects
| ID | Sev | Where (evidence) | Problem, in plain words | Fix |
|---|---|---|---|---|
| CRAWL-05 | **H** | `https://www.stellarscio.app/this-does-not-exist` → **200**, homepage HTML. `/PLATFORM` → 200, homepage. Cause: `vercel.json` catch-all rewrite `/((?!api/\|assets/).*)` → `/` | Any typo or dead link looks like a real page full of homepage content. Google calls this a "soft 404": it wastes crawl budget and can show junk URLs in search. | Narrow the SPA rewrite to the routes the app actually owns (`/app/*`, `/demo/*`). Add `public/404.html`, a small branded page marked noindex that links back home. Vercel serves it with a real **404** status for every other path. |
| CRAWL-08 | M | `src/AppRouter.tsx:88-104`: `/industries/*`, `/customers`, `/platform/control-tower`, `/resources`, `/energy`, `/maritime`, `/logistics`, `/dashboard`… redirect only through React `<Navigate>` | The server returns 200 + homepage HTML, and only the browser's JavaScript moves the visitor. Crawlers and link previews never see the redirect, so old backlinks pass no value. | Add the same redirects to `vercel.json` `"redirects"`: 301 for retired marketing pages (`/industries/*`, `/customers`, `/resources`, `/platform/control-tower`), 307 for the dashboard shortcuts (`/energy` → `/?industry=energy&tab=energy-dashboard`, etc.). Keep the React routes as a fallback. |
| CRAWL-03 | M | `curl https://www.stellarscio.app/app` → 200, `robots: index, follow`, canonical `/` | The private app tells search engines "index me". robots.txt blocks crawling `/app/`, but a blocked URL can still be listed if someone links it, and bare `/app` doesn't match `/app/`. | `vercel.json` header `X-Robots-Tag: noindex, nofollow` on `/app`, `/app/(.*)` and `/demo/(.*)`. Change robots `Disallow: /app/` to `Disallow: /app` so it covers both. |
| CRAWL-10 | L | `public/ad_card.html` is deployed at `https://www.stellarscio.app/ad_card` | An internal 1200×630 social-card design file is live and crawlable, so it could get indexed as a thin page. | Move it to `design/` (next to `design/thumbnail.html`), out of the deploy. |

**How we'll verify:** `npm run build`, then `vercel dev` (or a preview deploy) with curl checks: fake URL → 404, `/industries/x` → 301, `/app` → `X-Robots-Tag` present, all 8 sitemap URLs → 200. Then re-run `live_audit.py`.

## Kept on purpose
| Looks like | Decision | Why it stays |
|---|---|---|
| Inline `onload` handler on the font stylesheet (`index.html:124`) | Comment: "Fonts load without blocking the first paint" | It's the standard non-blocking font pattern. It goes away by itself if Batch 4 self-hosts fonts. |
| No FAQPage schema in prerendered HTML | Comment in `prerender-seo.mjs` | `FaqPage` adds it at runtime. Two FAQPage blocks on one URL is a Search Console error. |
| Same OG image for every page | Comment in `seo.ts` | One branded card by choice. `?v=4` busts chat-app caches. |
| Prerendered copy is visually hidden | Comment in `prerender-seo.mjs` | It's for crawlers and screen readers. `<noscript>` makes it visible when JS is off. |
| `/app` reachable only by URL, not linked | Comment in `AppRouter.tsx` | It's an unlisted product app. Batch 1 only adds noindex. |
| Homepage bundled in the main chunk | Comment in `AppRouter.tsx` | It avoids a loading screen on first visit. |
| `onnxruntime-web`, `react-is` flagged as "unused dependency" | `package-lock.json` | They're peer dependencies of `ppu-paddle-ocr` and `recharts`. Removing them breaks the build. |
| `src/lib/next-compat/navigation.ts` flagged "unused" | `vite.config.ts` alias `next/navigation` | It's imported through the alias. |
| Clickable divs, multiple `<h1>`, inline `<style>` in `src/demo/*`, `src/components/energy/*` etc. | Private app | Out of SEO scope. They can be a separate a11y pass on the app later. |
| `<meta name="keywords">` | n/a | Google ignores it and it's harmless. Left for other engines. |
